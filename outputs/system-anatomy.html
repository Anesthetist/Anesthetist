Section I

Ontological Architecture

The vault implements a four-layer epistemic stack, moving from raw evidence through embodied observation, to structured concepts, to audience-specific outputs. Each layer is governed by a standards framework (Dublin Core, SKOS, PROV-O) and enforced by a YAML schema definition. Notes do not float freely; they exist at a defined layer with defined relationships to adjacent layers.

The schema constraint file (_schema/note-types.yaml) defines six note types across four layers plus a source layer. Each type specifies required and optional fields. The type system enforces that no note enters the graph without a URN identifier (urn:srl:{type}:{slug}), a status gate (draft / review / canonical), and Dublin Core metadata. This is not advisory; the vault-writer bot will not create notes missing required fields.

Dublin Core

Descriptive metadata on every note

Title, creator, date, subject tags, source URNs, identifiers (DOI/ISBN). Applied across all layers. Provides the minimum interoperability surface for any information retrieval system to index the vault.

Concept relationships — the knowledge graph

Three relation types: broader (parent), narrower (child), related (lateral). Applied at Layer 1. The SKOS vocabulary provides taxonomic structure without requiring a formal ontology; concepts can have polyhierarchical relationships.

Section III

Epistemological Layers

The vault does not treat all knowledge as equivalent. Drawing from the Dreyfus model of skill acquisition and the cognitive ethnographer's framework, concepts distribute across a spectrum from established science to speculative extension. The quality gate (draft / review / canonical) is an epistemic status marker, not just an editorial one.

Section V

The Closed Epistemic Loop

What distinguishes this system from a conventional knowledge management tool is the closed feedback loop. Knowledge does not merely flow from sources to outputs. It cycles: outputs generate user data, user data feeds back into the graph as new evidence, evidence revises concepts, revised concepts reshape outputs. The system learns from its own deployment.

The dashed green arrow represents the feedback path that most knowledge systems lack. When a NeuroMinute is deployed and HRV biometric data returns from users, that data enters the vault as new evidence, which may confirm or revise the concepts that generated the output. This is not aspirational architecture — the pipeline from PubMed scans to vault notes to product outputs already runs. The user-data-to-evidence path is the next activation.

Section VI

Methodological Framework

The SRL Knowledge Vault is not a novel system in isolation. It operationalizes established frameworks from information science, organizational knowledge theory, and cognitive science. What is distinctive is the integration: no single prior system combines all four frameworks below into a functioning, agent-operated knowledge graph with provenance chains and a quality gate.

Nonaka SECI Model — Bot Mapping

Nonaka & Takeuchi (1995) describe four modes of knowledge conversion. The SRL vault maps each mode to specific agents and processes. The system operationalizes the full SECI spiral, which most knowledge management systems only partially implement (typically only Combination).

Schön's Reflective Practice

Schön, D. (1983). The Reflective Practitioner.

Schön distinguishes knowing-in-action (tacit), reflection-in-action (mid-situation adjustment), and reflection-on-action (post-hoc analysis). The SRL vault captures all three: observations encode knowing-in-action, ChatGPT conversations capture reflection-in-action, and the cognitive ethnographer's field notes perform reflection-on-action. The system makes Schön's three modes inspectable, versionable, and searchable.

Hutchins' Distributed Cognition

Hutchins, E. (1995). Cognition in the Wild.

Cognition in this system is distributed across: the founder's body (28 years of somatic pattern recognition), four AI platforms (ChatGPT, Claude, Gemini, Perplexity), the Obsidian vault (structured knowledge graph), wearable sensors (Polar H10, Muse, Apple Watch), 10 specialized bots, and 13 toolchain instruments. No single node holds the complete system intelligence. The vault is the coordination medium — the shared representational space that Hutchins describes as essential for distributed cognitive systems.

Benner's Novice-to-Expert

Benner, P. (1984). From Novice to Expert.

The quality gate (draft → review → canonical) is an epistemic version of Benner's staging. Draft concepts are novice-level knowledge — identified but not yet grounded. Canonical concepts are expert-level — richly linked, evidence-backed, and human-validated. The system tracks its own epistemic maturation note by note, producing a visible progression that Benner describes as largely invisible in clinical practice.

The Closed-Loop Contribution

SRL's operationalization, 2023–2026.

What this system adds to prior work: it closes the loop. Nonaka describes the SECI spiral but does not build it as software. Schön describes reflection but does not version-control it. Hutchins describes distributed cognition but does not wire it with provenance chains. Benner stages expertise but does not tag notes with Dreyfus levels. The SRL vault operationalizes these frameworks into a functioning, git-tracked, agent-operated, standards-compliant knowledge graph. The integration is the contribution.

Section VII

Structural Observations

A post-doctoral reviewer examining this system should note several structural properties that distinguish it from conventional knowledge management:

1

The observation layer (L0.5) is an epistemic innovation.

Most knowledge graphs go directly from evidence to concept. SRL interposes a layer for embodied/clinical knowledge — the practitioner's pattern recognition, craft knowledge, and somatic markers. This layer has 230 notes, more than concepts (156), indicating that the system's center of gravity is experiential, not bibliographic. This is consistent with Polanyi's observation that "we know more than we can tell."

2

The evidence-to-concept ratio (1.75:1) indicates healthy epistemic density.

Each concept is supported on average by nearly two evidence notes. This is not a speculation engine; it is a system that requires evidentiary grounding. The hub concept (clinician-durability, 55 refs) is among the best-wired in the graph, reflecting its centrality to the research program.

3

The bot system implements reflexive improvement.

Each bot has learning logs and pattern libraries that accumulate across runs. The extraction coordinator tracks system-level trends. This is not a static pipeline; it is a system that improves its own extraction, validation, and writing processes over time. Three feedback loops operate: within-bot reflexion, cross-bot evaluation, and founder-decision feedback.

4

Git as lab notebook is methodologically significant.

The commit history is designed to read as a research log. Every extraction, enrichment, and wiring operation is version-controlled with commit messages that record what changed, why, and from which sources. This provides temporal reproducibility: any reviewer can reconstruct the vault's state at any prior point and trace how knowledge evolved.

5

The system is a case study in human-AI distributed cognition.

The vault represents one of the most detailed artifacts of an expert's knowledge externalization process mediated by AI. The 861 ChatGPT conversations constitute a longitudinal dataset of tacit-to-explicit knowledge transformation. The cognitive ethnographer bot explicitly treats this as ethnographic data. The vault itself is both the product and the record of a distributed cognitive system in operation.
