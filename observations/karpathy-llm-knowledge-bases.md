# Karpathy — LLM Knowledge Bases as Personal Research Infrastructure

## Source
Andrej Karpathy (@karpathy), April 2–5, 2026. [https://x.com/karpathy](https://x.com/karpathy)

## Key Insight
Karpathy describes a shift in his LLM usage from code manipulation to building personal knowledge bases for research topics. He shares the concept of an "idea file" — in the era of LLM agents, the specific code/app matters less than the idea itself, since agents can execute implementations. His token throughput now flows primarily into knowledge curation rather than code generation.

## SRL Relevance
This validates SRL's vault-as-research-infrastructure approach. The Library-Graph architecture already implements exactly this pattern: structured knowledge bases that LLM agents (like the Vault Librarian) curate and query. Karpathy's signal that elite AI practitioners are moving toward knowledge-base-first workflows confirms that SRL's investment in vault architecture is directionally correct and potentially ahead of the curve. The "idea file" concept also maps to SRL's concept notes — capturing the generative idea rather than the implementation.

## Red Arrow
**Arrow 4: Enterprise Data → Clinical LLM Moat** — If industry leaders are building LLM knowledge bases, SRL's structured vault (with SKOS wiring, evidence chains, and compliance metadata) represents a defensible moat. The structured, domain-specific knowledge graph is more valuable than general-purpose LLM capabilities.
