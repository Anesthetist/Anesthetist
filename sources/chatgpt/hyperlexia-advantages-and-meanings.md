## Deep dive
### The key move: separate “what it is” from “what happened”
If you want rigor + scalability, the ontology needs a hard boundary between:

- **Protocol** = the *recipe* (what you prescribe)  
- **Session** = the *execution* (what the user actually did)

That separation is what makes it possible to:
- run A/B comparisons between protocol variants
- attach **contraindications** to the protocol (and not “the user”)
- attach **measurement context** to the session (and not to the protocol)
- keep claims clean (protocol *aims for* outcomes; session *has observations* that may indicate state changes)
