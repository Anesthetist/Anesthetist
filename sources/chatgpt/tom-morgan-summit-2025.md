#### How this maps to Somnistics’ roadmap

1. **Start lightweight (weeks 1-2).**  
   Spin up `server-memory` inside your dev docker-compose. It’s one command (`npx @modelcontextprotocol/server-memory`) and stores a JSONL graph—enough to test how CRNA user facts survive across NeuroMinute sessions.

2. **Add human-readable backups (month 1).**  
   Layer **Basic Memory** so all session nodes are mirrored to Markdown files in an Obsidian vault. That gives you versioning, diff-able change history, and an easy “open-science” backup.

3. **Graduate to typed graphs (quarter 1).**  
   When you need richer relations—e.g., mapping HRV-pattern → suggested script version—migrate to **MemoryMesh**. Its schema designer lets you declare entities like `BioMarker`, `Intervention`, `Outcome`, then auto-generates MCP tools to CRUD them.

4. **Enterprise / multi-tenant phase (post-Series A).**  
   Evaluate **Cognee** or the **libSQL** fork once you a) log hundreds of thousands of biometric rows daily and b) want vector similarity built in. Both bring heavier infra (Postgres/Modal/Redis) but offer scaling headroom.

5. **Specialized connectors.**

An **MCP “memory server”** is just a small program that stores and recalls facts for your AI agents (e.g., “Randy’s HRV baseline is 54 ms”). Imagine Apple Notes that a bot can query in milliseconds.
